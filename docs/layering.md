# 持续规则、技能和自动检查怎么分工

技能适合保存一项任务的完整做法；持续规则适合声明每次项目任务都要遵守的约定。把技能装进目录，不等于助手会在每个任务中自动使用它。

## 按用途选择

| 方式 | 在这里做什么 | 适合的内容 |
| --- | --- | --- |
| 全局或项目 `AGENTS.md` | 由支持该约定的助手加载到指令上下文 | 输出偏好、项目边界、开工前要读的技能入口 |
| `SKILL.md` | 点名调用，或由助手按任务选择后读取 | 多步骤流程、示例、按需加载的参考材料 |
| 项目脚本、hook、CI | 在指定命令或事件中运行程序 | 格式、语法、文件引用、测试等可机械验证的问题 |
| 网页产品的自定义指令 | 保存该产品支持的持续偏好 | 对话语气、读者假设、常用表达要求 |

文件被加载，只说明规则已经提供给模型，不保证每次都能正确执行。自动检查也只覆盖程序实际实现的规则，不能代替语义审阅、事实核验或功能验收。

## 让维护技能成为项目任务的默认约定

Codex 的用户级规则通常在 `~/.codex/AGENTS.md`，OpenCode 在 `~/.config/opencode/AGENTS.md`。保留已有内容，追加一段指向本机技能文件的约定，例如：

```text
开始代码项目的开发、修改、重构或维护任务前，先读取并应用本机 ~/.agents/skills/agent-maintenance/SKILL.md，再按本次任务读取相关参考。
同时读取目标项目的 AGENTS.md，复用已有源码、文档和检查入口。用户明确指令优先；技能不扩大部署、发布或合并权限。
纯问答、翻译和固定格式输出不启动项目改造。
```

将 `~` 换成助手能正确解析的实际用户目录。Windows PowerShell 读取中文 UTF-8 文件时使用 `Get-Content -Encoding UTF8`；遇到终端乱码，应先核对读取和输出编码，不能据此修改源文件。

保存后用新会话验证：让助手说明它实际读取了哪个入口，查看工具记录是否真的打开该文件。已有会话是否重新加载，取决于产品；Codex 在新的运行或会话开始时构建指令链。有自定义 `CODEX_HOME` 或 `AGENTS.override.md` 时，以实际加载配置为准。

## 保持规则简短且有归属

常驻规则写约定和入口，完整流程留在技能中。不同位置不要重复维护几份完整说明，避免一份更新、另一份过时。

例如，“面向不熟悉领域的读者解释必要术语”适合常驻规则；如何保留命题、改写和验收适合 `plain-language-zh`。文档链接是否存在交给检查器，文档结论是否符合实现仍要核对源码和测试。

可直接复制的写作规则见[配置模板](prompt-templates.md)。产品支持范围见 [Codex AGENTS.md](https://developers.openai.com/codex/guides/agents-md/)、[Codex 技能](https://developers.openai.com/codex/skills/)、[OpenCode 规则](https://opencode.ai/docs/rules/)和[OpenCode 技能](https://opencode.ai/docs/skills/)。
