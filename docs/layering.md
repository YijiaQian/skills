# 常驻规则与技能怎么分工

整理日期：2026-10-29。回答两个问题：为什么只靠技能不够，以及"说满"这类问题该怎么修。

## 一、先回答：需不需要打 `$`

不需要，但也不能指望它每次自己触发。

Codex / ChatGPT 的技能采用渐进披露：会话开始时只把每个技能的 `name` 和 `description` 放进上下文（Codex 还带文件路径，这段预算默认最多占上下文的 2%，或 8000 字符），模型判断当前任务匹配某个描述后，才读取完整的 `SKILL.md`。所以存在两条路径：

1. 显式调用：`$plain-language-zh`、`/skills`，或 ChatGPT 里打 `@`。
2. 隐式调用：模型自己按 `description` 匹配。

也就是说 `$` 是"强制手段"，不是日常必需。代价是隐式匹配**是概率性的**：描述里没有的词，模型就可能不触发。你让它"写一份方案"，如果描述只写了"解释和改写"，大概率不会命中。

## 二、要"一直生效"，该放在哪一层

| 层 | 什么时候进上下文 | 谁决定 | 确定性 | 每次成本 | 适合放什么 |
| --- | --- | --- | --- | --- | --- |
| `AGENTS.md` | 每轮开始，全量注入 | 无决定环节 | 确定 | 几百字 | 常驻偏好、红线、判据 |
| 技能 | 先放 name + description，命中后读全文 | 模型 | 概率性 | 触发后 1–6k token | 多步骤流程、示例、脚本 |
| hooks | 生命周期事件触发 | 配置 | 确定 | 极小 | 格式化、拦截危险命令 |
| 网页端自定义指令 | 每次对话注入 | 平台 | 确定 | 中 | 个人偏好（ChatGPT 自定义指令、Gemini 个性化指令） |
| 输出风格 | 会话级 | 用户切换 | 选定后确定 | 中 | 整体文风（Claude Code output styles） |

由此得到的分工：

- **每条回复都要生效的规则 → 常驻指令文件。** 这是唯一不依赖"模型今天心情好不好"的层。
- **完整流程、示例、验收清单 → 技能。** 平时不占上下文，需要时再读。
- **必须无条件执行的 → hooks。** 但 hooks 挂在工具调用等生命周期事件上，没有"模型刚写完一段正文"这个事件，所以**不能用它来删废话或改文风**。这条容易误解，专门记一下。

## 三、"自感知"要怎么写才真的自感知

关键不在形容词，在**触发条件写给谁看**。

- 无效写法："当用户提到可读性、黑话、术语时……"——这仍然依赖你当时的措辞，等于还是要手动。
- 有效写法："面向人阅读的回复、文档、方案、评审意见和总结……"——模型看得到自己正在产出的东西，能从任务类型判断。
- 更稳的一层：给一条**能在草稿上自检的判据**，例如"删掉这条限制，读者会不会做出错误决定？不会就不写"。判据比"要简洁""要清楚"这类形容词可靠，因为模型可以在交付前拿自己的稿子过一遍。

这也是把规则放 `AGENTS.md` 而不是塞进技能描述的原因：技能描述要做匹配，只能写场景词；常驻文件可以写判据。

## 四、关于"说满"

你举的例子是写文档时列一串"缺少集成测试、缺少 X、缺少 Y"。这类清单大多不是读者需要的信息，而是模型在证明自己谨慎。两个改法：

1. **换对象。** 从"我还没做什么"改成"这个结论在什么条件下成立"。"缺少集成测试"是待办项；"只跑过单元测试，没连过真实数据库，所以'不影响现有导入'还没验证"是结论边界。
2. **给判据。** 删掉这条，读者会不会做出错误决定？不会就删。同类合并成一句，别一条一行。

诚实性不降：会影响结论的事实限制照样必须写，只是不再每条一行、不再用"建议进一步……"凑收尾。这条边界写进了技能的"限制、风险与免责怎么给"一节，并配了两个示例（原稿 → 参考 → 验收点）。

## 七、还没验证的

- 没有做 GPT / Gemini 同题对照，也没有测触发率。规则能不能稳定压住清单式免责，要在你的真实文档上抽查几次。

- `AGENTS.md` 的加载顺序与长度上限随版本变化，以实际版本为准；有 `AGENTS.override.md` 或自定义 `CODEX_HOME` 时以自己的配置为准。
- OpenCode 这边规则靠 `AGENTS.md` 生效，技能未被 OpenCode 的技能目录发现（技能装在 `.codex/skills`）。若想让它也能被 `skill` 工具调用，可在 `opencode.json` 里加 `"skills": { "paths": ["C:\\Users\\q1014\\.codex\\skills"] }`；本次没有改，未验证该字段在当前版本的行为。
